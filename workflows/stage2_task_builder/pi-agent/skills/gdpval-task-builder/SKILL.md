# GDPval 复杂题目构建

把当前 `task_NNN` 当作唯一工作边界。必须完成实际文件，不要只给计划或自然
语言结论。只能使用本 Skill 提供的自定义工具。

## 核心顺序

严格按以下顺序执行，不得先写 query 再找附件：

1. 调用 `candidate_inventory` 获取全部20个候选及原始 query。
2. 按主体、报告期、文档类型和证据功能把候选划分为至少四组。
3. 并行使用 `search_evidence`，并用 `read_candidate` 核对拟作为核心证据的原文。
4. 比较至少两个实质不同的职业任务方向。
5. 调用 `set_task_direction` 保存备选方向、证据范围、主要风险及最终选择理由。
6. 初选10至17个最终附件，包含核心、辅助和少量合理干扰材料。
7. 仅在可回答性存在缺口时，调用 `create_generated_attachment` 创建0至3个辅助
   文件。
8. 调用 `assemble_final_attachments` 固化最终附件和选择清单；工具会按最终
   顺序把文件重新编号为 `01__` 至 `NN__`。
9. 只根据已经固化的附件能力反向设计至少12步的 `workflow.md`。
10. 再把任务目标压缩为 query“具体任务”中的一个整体叙述段落，不把 workflow
    步骤复制进 query。
11. 调用 `finalize_task` 一次性写入 workflow、query、证据矩阵和质量审查，
    并以外部校验通过作为结束条件。

工具会拒绝越界或顺序错误。遇到工具错误时，根据原始错误修正参数后重试。

## 证据分析

对每个拟选文件判断：

- 主体、报告期、文档类型和信息来源；
- 可支持的财务、经营、风险、监管或市场判断；
- 关键证据在抽取全文中的页码标题、工作表或行号；
- 与其他文件的互补、重复、口径冲突和时间错配；
- 适合作为 `core`、`supporting`、`purposeful_noise` 还是排除；
- 数据缺口、答案泄漏风险以及是否需要任务假设。

不得只依赖摘要。核心事实至少经过一次全文搜索或片段读取。区分原文事实、
答题者需要计算的结果和专业判断，不得把后两者写进生成附件。

## 题目方向

备选方向必须在业务决策目标和核心分析方法上有实质差异，不能只是换标题。
优先选择同时满足以下条件的方向：

- 附件能够支持所有必要结论，不依赖联网或未披露事实；
- 合格专业人员需要至少10小时；
- workflow 至少12个具有真实前后依赖的步骤；
- 主要价值来自跨文档核对、定量建模、情景设计、行业洞察和原创判断；
- 需要处理口径冲突、信息缺口或高噪声，而不是复制现成评级结论；
- 最终成果可以直接用于投资委员会、管理层、风控委员会或类似真实场景。

单一企业材料不足时，优先构造同业横向比较、投资组合、信用评估、风险压力
测试或战略决策任务。

## 最终附件

最终附件总数必须为10至17个：

- 候选附件只能来自当前 `candidate_manifest.json`；
- 生成附件最多3个，并计入总数；
- 最终文件名必须使用装配工具重新生成的连续编号，不能沿用候选rank；
- 至少保留两个核心证据文件；
- 保留少量看似相关、但需要专业判断才能识别的干扰材料；
- 混合不同主体、报告期、文档类型或文件格式；
- 不在 query 中标注哪些文件是干扰项。

生成附件只能是：

1. 明确标记的任务假设或情景参数；
2. 从候选原文整理、并保留 `document_id` 来源的结构化汇编。

生成附件不得伪装成外部出版物，不得计算最终评分、评级、压力测试结果、
投资结论或管理建议。CSV 的 `payload` 使用：

```json
{"rows":[["字段1","字段2"],["值1","值2"]]}
```

XLSX 的 `payload` 使用：

```json
{"sheets":[{"name":"参数表","rows":[["参数","数值"],["情景A",1.0]]}]}
```

## 反向设计 Workflow 和 Query

附件固化后，再回答三个问题：

1. 这些附件共同支持什么具体决策？
2. 为得到该决策，答题者必须完成哪些相互依赖的工作？
3. 哪1至5个实际文件能够承载全部成果？

先把完整工作方法写入 `workflowMarkdown`。workflow 使用从1开始的连续编号
列表，至少12个实质步骤：

- 明确前置数据整理、并行分析、交叉验证和后续综合之间的依赖；
- 包含定量分析、专业判断、情景或敏感性分析及原创建议；
- 不使用可合并的重复步骤凑数量；
- 不要求附件之外的数据或联网研究；
- 作为内部任务设计材料，不在 query 中提及 `workflow.md`。

随后单独编写 query。query 不得复述关键数值、现成结论、附件选择理由、干扰
文件身份或 workflow 的详细步骤。附件中的信息应由答题者发现，而不是在题干
中泄漏。

query 必须严格且仅包含以下三个 Markdown 二级标题：

```markdown
## 任务背景

## 具体任务

## 交付要求
```

### 任务背景

使用连贯段落说明任职角色、委托方、业务情境、决策目的和材料边界。不要列举
附件清单，不要提前给出分析结论。

### 具体任务

只使用一个120至320字的连贯段落，从整体上说明需要完成什么专业任务、需要
综合哪些层面的材料、最终要支持什么决策。不得使用编号、项目符号、小标题或
分步骤措辞；不得逐项指定指标、公式、阈值、分析动作和结论结构。为答题者保留
方法选择、建模路径和专业判断空间。不得出现“步骤、逐份、逐项、手工、提取、
计算、页码、工作表、公式、权重、阈值、评分模型”等 workflow 级方法词。

合格的“具体任务”应接近以下抽象程度，不要照抄：

> 请基于所提供材料，完成一项面向投资决策的金融机构同业经营与风险比较研究，
> 综合评估不同机构的财务质量、经营韧性和潜在风险，形成具有可追溯依据的专业
> 判断和差异化建议。分析应妥善处理材料间的报告期、口径和信息完整度差异，
> 体现必要的定量验证与行业洞察，但具体方法、模型结构和判断框架由答题者自行
> 设计。

### 交付要求

必须以“请提交以下 N 个文件：”开头，其中 N 为1至5。随后连续编号列出具名
文件，文件名和扩展名放在反引号中，例如：

```markdown
请提交以下 2 个文件：
1. `信用风险评估报告.docx`：……
2. `压力测试与评分模型.xlsx`：……
```

章节、工作表、附录和图表属于对应文件，不单独计为交付物。清单之外不得额外
要求摘要、说明、演示稿或数据表。

## 内部审计材料

传给 `finalize_task` 的 `evidenceMatrixMarkdown` 至少包括：

- workflow 每个步骤对应的附件；
- 核心事实的页码标题、工作表或抽取行号；
- 口径冲突、报告期差异和信息缺口；
- 生成附件的用途和来源。

`qualityReviewMarkdown` 至少检查：

- 可回答性及外部数据依赖；
- 10小时级复杂度和12个以上步骤的真实依赖；
- 专业创造性是否占主导；
- 关键数值、结论和干扰项是否泄漏；
- 附件数量、生成附件数量、候选边界和重复证据；
- workflow/query 是否分离、具体任务是否单段、三段式结构和1至5个具名
  交付文件；
- 每项交付能否由实际附件复核。

内部材料不得在 query 中引用。

## 完成条件

必须以 `finalize_task` 返回“passed deterministic validation”结束。工具失败时
只修复指出的问题；附件组合发生变化时，重新装配后再重写 query。不得以
“已经完成”“校验通过”等模型自述替代工具结果。
