# 参考风格包 `ref-semi`（某半导体 2026Q1 真实底稿/报告风格）

本风格包从以下真实交付物逆向提取，作为 `golden-solution-pro` 的一套**参考风格**（彩色，非黑白）：

- `某半导体_2026Q1_合规与财务分析报告.docx`（Word 报告 + 内嵌表格）
- `某半导体_2026Q1_核查与复算底稿.xlsx`（Excel 复算底稿）
- `某半导体_2026Q1_风险与跟踪台账.xlsx`（Excel 风险台账）
- `关键数字核验表 (1).csv`（CSV 关键数字核验）

> 与 `word-A/B/C`、`excel-A/B/C` 的关系：A/B/C 是**黑白**风格包（受 `_is_grey` 守卫强制去色），用于通用轮换。`ref-semi` 是**彩色参考**风格包，忠实复刻上述真实文件，用于需要与半导体/审计底稿观感对齐的产物。`ref-semi` 在 `render.py` 中以 `allow_color=True` 跳过 `_is_grey` 守卫，直接使用真实色值。

---

## 一、Word 报告风格（`word-ref`）

### 1. 页面
- 纸张：Letter（8.5×11 in / 21.59×27.94 cm），单栏。
- 页边距：上下 1 in（2.54 cm），左右 1.25 in（≈3.17 cm），页眉/页脚 0.5 in。
- 文档网格 `docGrid` linePitch=360（默认）。

### 2. 字体（正文与表格统一）
- **正文字体**：宋体 SC（`Songti SC Regular`）。`ascii / hAnsi / eastAsia / cs` 四通道全部设为该字体，`hint=eastAsia`。
- **字号**：
  - 正文主体：10.5 pt（`sz=21`）。
  - 细则/编制基础/免责等小字：9 pt（`sz=18`）。
  - 表格表头：9.5 pt（`sz=19`）加粗。
  - 表格单元格正文：9–10.5 pt。
- 颜色：全部 `auto`（黑），除表头白字外不出现彩色字体。

### 3. 段落
- 行距：单倍（`line=240, lineRule=auto`），段后间距 0。
- **无首行缩进**（全篇不缩进）。
- 对齐：标题块居中；正文左对齐；表格表头/居中列居中。

### 4. 标题层级（不使用 Word 内置 Heading 样式，直接段落级格式）
| 层级 | 字号 | 加粗 | 编号体系 | 示例 |
|---|---|---|---|---|
| 文档主标题 | 20 pt（`sz=40`） | 加粗 | — | 某半导体有限公司（A+H 双重上市） |
| 文档副标题 | 16 pt（`sz=32`） | 加粗 | — | 2026 年第一季度合规与财务分析报告 |
| 编制/署名行 | 10.5 pt | 不加粗 | — | 董事会秘书办公室·证券事务合规组｜基准日期：2026-05-15 |
| 一级标题 H1 | 15 pt（`sz=30`） | **不加粗** | 一、二、三 | 一、取数口径与相似文件辨析 |
| 二级标题 H2 | 12.5 pt（`sz=25`） | **不加粗** | 1.1 / 1.2 | 1.1 取数对账矩阵 |
| 执行摘要等小节 | 15 pt | 不加粗 | — | 执行摘要（一页） |

> 关键差异点：标题**不加粗**，靠字号与编号区分层级；这是审计/合规报告的典型观感，与公文（黑体加粗标题）截然不同。

### 5. 表格（`Table Grid` 样式，全网格）
- 表样式：`Table Grid`（基于 Normal Table）。
- 边框：上下左右 + 内横 + 内纵，全部 `single`、`sz=4`（0.5 pt）、`color=auto`（黑）——**全网格细黑边框**，非三线表。
- 表属性：`tblW=auto`、`tblLayout=autofit`、`jc=center`（整表居中）。
- 单元格边距：上下 0 dxa，左右 108 dxa（≈0.19 cm）。
- 表头行：底纹 `1F4E78`（深蓝），文字加粗、9.5 pt、居中。
- 强调单元格底纹（用于标注数据性质，与 Excel 底稿一致）：
  - `FCE4D6`（浅橙）：提示/注意/风险得分。
  - （在 Excel 中还有 `FFF2CC` 输入黄、`E2EFDA` 公式绿；Word 报告表格中主要出现深蓝表头 + 浅橙强调。）
- 题注：表上方，`表N 标题`，居中，10 pt 加粗深灰。
- 脚注：表下，`数据来源：……`，9 pt 深灰。

## 二、Excel 底稿/台账风格（`excel-ref`）

### 1. 工作表结构（每张表通用骨架）
```
行1：标题行    —— A1:<ncol> 合并，13 pt 加粗，字色 1F4E78（深蓝），垂直居中，行高 22
行2：说明行    —— A2:<ncol> 合并，11 pt，自动换行，顶端对齐（可省略）
行3：表头行    —— 见下
行4..：数据行  —— 见下
行N+1：空行
行N+2：注释行  —— A 合并，加粗标签 + 11 pt 说明
```

### 2. 标题行（行 1）
- 合并 `A1:<末列>`，行高 22。
- 字体：13 pt、**加粗**、字色 `1F4E78`（深蓝）。
- 左对齐、垂直居中。

### 3. 表头行（行 2 或 3）
- 字体：11 pt、**加粗**、字色 `FFFFFF`（白）。
- 底纹：`1F4E78`（深蓝）。
- 对齐：水平居中 + 垂直居中 + `wrap_text=True`。
- 边框：四边 `thin` 黑。

### 4. 数据单元格
- 字体：Calibri 11 pt，黑字。
- 边框：四边 `thin` 黑（全网格，与 Word 表格一致）。
- 对齐：
  - 编号/代码列（如 R1/R2、F1/F2、序号）：水平居中 + 垂直居中 + 换行。
  - 文本/说明列：顶端对齐 + `wrap_text=True`（左对齐）。
  - 数字列：右对齐。
- 行高：数据行加高（46–64）以容纳换行文本。
- 列宽：按列内容显式设定（不依赖默认）。

### 5. 数字格式（按列语义，由内容层在 `col_fmt` 指定）
| 语义 | number_format | 示例 |
|---|---|---|
| 人民币元（A 股口径） | `#,##0.00` | 4,625,372,637.73 |
| 千元/美元千元（H 股口径） | `#,##0` | 660,925 |
| 比率/EPS 元 | `#,##0.00` | 0.08 |
| 百分比 | `0.00%` | 18.22% |
| 公式结果（折算） | `#,##0` | 4,626,475 |

### 6. 数据性质色码（底稿核心特征）
单元格底纹按"数据怎么来的"着色，这是审计复算底稿区别于普通报表的关键：
| 底纹色 | hex | 含义 |
|---|---|---|
| 黄 | `FFF2CC` | **输入**——直接取自附件原值（input） |
| 绿 | `E2EFDA` | **公式**——由公式/交叉计算得到（compute） |
| 橙 | `FCE4D6` | **提示/注意**（caution，如风险得分=概率×影响=中高） |
| 浅橙 | `F8CBAD` | **风险得分高亮**（risk，=概率×影响结果格） |
| 无底纹 | — | 文本/说明/引用 |

> 内容层通过表格 spec 的 `kinds` 矩阵（与 `rows` 同形）标注每个数据格的性质：`input / compute / caution / risk / text`；缺失则按 `text` 无底纹。

### 7. 图例（Legend）
首个/说明工作表底部应有色码图例三行：
```
黄（FFF2CC）｜输入：直接取自附件原值
绿（E2EFDA）｜公式：由公式交叉计算得到
橙（FCE4D6）｜提示：口径/分歧/注意
```

### 8. 注释行
- 表下空一行，`A` 列写"备注"/"说明"加粗 + 同行说明文本 11 pt。

### 9. 冻结
- 本批真实文件未启用冻结首行（`freeze_panes=None`）。`excel-ref` 默认不冻结，与参考一致。

## 三、CSV 关键数字核验表风格（`csv-ref`）

### 1. 编码与分隔
- 编码：**UTF-8 with BOM**（`utf-8-sig`）。
- 分隔符：`,`；引号：`"`；行尾 CRLF。

### 2. 七列固定表头
```
指标, 数值, 单位, 来源文件, 页面/章节/定位, 计算公式, 结论/校验
```

### 3. 数值书写规则（与 Excel 单元格原值一致，不经格式化）
- **不加分隔千分位**：`4625372637.73`，而非 `4,625,372,637.73`。
- 负数前置 `-`：`-160655048.90`。
- 比率以小数 + 括注百分比：`0.1822(=18.22%)`。
- 计算公式列保留可读中缀式：`营业利润-162150897.77+营业外收支(1578241.37-82392.50)`。
- 结论列含数值与校验注：`139562597.00(四舍入0)`、`一致`、`不适用`。

### 4. 渲染约束
- CSV 不承载样式，靠"列语义固定 + 数值原值不格式化 + 公式可读"传递可复算性。
- `render.py` 渲染 CSV 时**不做千分位格式化、不做四舍五入**，原样写出 content spec 的数值字符串。

## 四、内容层（agent）使用方式

content.json 指定：
```json
{
  "style_pack": "word-ref",          // 或 excel-ref / csv-ref
  "tables": [{
    "headers": [...],
    "rows": [[...]],
    "kinds":  [["input","compute",...]],   // 仅 excel-ref 需要
    "col_fmt": ["#,##0.00","#,##0",...],   // 仅 excel-ref 需要
    "caption": "...", "note": "..."
  }]
}
```

agent 须按上述规则起草：标题不加粗、表格全网格、Excel 底稿按数据性质着色、CSV 原值不格式化。

## 五、为何保留这套彩色参考

`golden-solution-pro` 默认黑白是为了"避免 AI 风格趋同"。但审计/合规真实底稿恰恰依赖**色码传递数据血缘**（输入黄/公式绿/提示橙）。`ref-semi` 把这套真实观感固化为可复用风格包，使产物与半导体/审计行业交付物对齐，而非泛黑白报表。`_is_grey` 守卫仅在 A/B/C 黑白包生效，`ref-semi` 以 `allow_color` 显式放行。
