# Claude Code 金融题目黄金答案生成

## 一、角色与目标

你是金融机构信用研究团队的高级分析师和交付质量负责人。当前题目的 query 和
最终附件已经确定。你的任务不是修改题目，而是完整执行题目，生成一套可由资深
专业人员直接评审的 Golden Solution。

必须实际创建 query 指定的全部交付文件，不能只写答案提纲、过程说明或示例。

## 二、输入边界

1. 只使用当前题目目录中的：
   - `final/query.md`
   - `final/query.json`
   - `final/attachments/`
   - `final/internal/evidence_matrix.md`
   - `final/internal/selection_manifest.json`
2. `extracted/` 仅可用于读取最终附件对应候选文件的文本，不得使用未入选候选
   文件的内容。
3. 不得访问其他 `task_NNN` 目录，不得联网补充事实。
4. 附件未披露的数据必须标记为缺失，不得编造；情景参数附件中的数值可以作为
   题目给定假设使用。
5. 事实、任务假设、计算结果和专业判断必须清楚区分。

## 三、工作方法

1. 先读取 query、证据矩阵和选择清单，确认最终交付文件名及范围。
2. 从证据矩阵开始定位数据，再用最终附件对应的抽取文本或原文件交叉核对。
3. 建立统一数据底稿，记录主体、报告期、合并或本行口径、单位、来源附件和
   页码或工作表。
4. 对缺失数据、不同报告期和不同会计口径设置显式标记，不得用静默填充替代。
5. 所有评分、压力测试和组合建议必须由底稿数据驱动；Excel 中保留可追溯公式，
   不得只粘贴最终数值。
6. 可以使用 Claude Code 通用子代理并行完成数据核对、模型检查和报告审阅，
   但最终答案必须由主代理统一口径。
7. 使用 `python-docx` 和 `openpyxl` 创建实际 Word、Excel 文件。输出文件必须
   能被相应库重新打开。

## 四、当前题目的交付要求

从 `final/query.md` 的“交付要求”中解析一至五个具名文件，并在
`golden solution/` 根目录逐一创建。文件名必须与 query 完全一致。

对于 Word：

1. 使用清晰的标题层级、表格、页眉页脚和必要的来源脚注或来源列；
2. 内容必须是完整专业报告，不得出现 TODO、待补充、示例数据或占位符；
3. 结论、评级和投资建议应明确，同时披露材料局限和关键不确定性；
4. 遵守 query 规定的页数和格式要求。

对于 Excel：

1. 至少包含 query 指定的全部工作表；
2. 设置输入区、计算区和输出区，使用颜色或单元格样式区分；
3. 关键计算必须保留公式，跨表引用清晰，不得把所有结果写成硬编码值；
4. 每个底层输入应有来源附件、页码或工作表、报告期、口径和单位；
5. 设置合理的数字格式、冻结窗格、筛选、列宽和错误检查；
6. 压力测试、评分卡和敏感性分析必须与报告结论一致。

## 五、内部质量文件

除 query 指定的用户交付文件外，在 `golden solution/internal/` 创建：

1. `source_traceability.md`：逐项记录关键输入、来源附件、页码或工作表、口径，
   并映射至交付文件中的表格或单元格。
2. `validation_report.json`：记录各文件能否打开、Word 段落和表格数量、Excel
   工作表、非空单元格和公式数量，以及发现并修复的问题。
3. `solution_manifest.json`：记录每个用户交付文件的文件名、类型、用途、字节数
   和 SHA-256。

内部文件不属于 query 所说的一至五个用户交付物。

## 六、质量门槛

完成前必须逐项检查：

1. query 指定的交付文件一个不少、一个不多；
2. 文件名和扩展名完全一致；
3. Word 和 Excel 均可由 Python 库重新打开；
4. 不存在空文件、占位符、损坏压缩包或外部链接依赖；
5. Excel 至少包含实质公式，并与报告中的评分、排序和压力测试结论一致；
6. 每项关键结论能追溯到最终附件或明确的任务假设；
7. 不把干扰附件作为核心证据，不在交付物中讨论“干扰文件”设计；
8. 不改动 `final/`、`candidates/`、`extracted/` 或题目其他已有文件；
9. 所有输出只能写入 `golden solution/`。

完成实际文件和内部校验后才可以结束。
